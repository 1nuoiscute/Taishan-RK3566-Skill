# Skill 回归场景

修改 Skill、模板或参考资料后，至少执行一个相关场景，记录输出是否满足断言。

以下“新输入”是专门用于行为回归的合成提示，不代表真实赛题、真实硬件配置或已完成实测。

## 核心必跑输入

### R1：只给陌生题面

**输入**：

```text
使用 $taishan-rk3566 帮我分析这道陌生视觉题：摄像头观察一个允许布置的平面区域，
系统需要给出若干规则图形的位置，并按题面规定的误差和时间判分。帮我做。
```

**通过断言**：

- 先输出需求卡或等价缺口清单，并主动询问/标记板卡、系统、摄像头、接口和完整题目约束；
- 分开写已确认事实、用户选择、合理假设和待验证项；
- 给出主/次视觉类型、推荐路线、最小验证、失败判据和降级路线；
- 因题面不完整，门禁只能“部分通过”或“阻塞”，不得生成完整工程；
- 不固定摄像头设备号、协议、GPIO、模型或性能数字。

### R2：只问 UART 低风险测试

**输入**：

```text
我第一次用泰山派，只想低风险检查 UART 设备是否可见、能否只读打开。
我不知道设备号、波特率和对端协议，不要发送任何数据。
```

**通过断言**：

- 使用快速验证需求卡或等价信息集；
- 先枚举/只读探测，再让用户基于证据选择候选设备和参数；
- 明确预期输出、退出/失败含义、证据保存方式和下一步；
- 不发送数据，不定义协议，不生成闭环工程，不把“能打开”写成“对端通信成功”。

### R3：已有工程增加功能

**输入**：

```text
我提供的已有相机工程入口是仓库中的 scripts/probe_camera.py。
请在保留现有 CLI 参数、退出码和已有 JSON 字段语义的前提下，
增加“连续帧采集达到用户确认的稳定条件后才判定稳定”的功能。先检查工程，不要重写。
```

**通过断言**：

- 先读取工程入口、配置、测试和现有接口，建立增量改造卡；
- 未拿到文件时只列最小材料清单，不臆测代码结构；
- 记录原行为基线、最小修改面、回滚办法和原有/新增行为回归；
- 保留已确认接口，不擅自修改设备号、协议、坐标，也不替用户确定“稳定”的阈值或采样条件；
- 只有读完相关代码且基线可验证后才实施局部修改。

### R4：已有 YOLO 模型要求部署到 RK3566

**输入**：

```text
我已有 best.pt，想在泰山派 RK3566 上用 YOLO 实时识别。先给我最短能验证的部署路径，
并告诉我静态图检出后还必须验证什么。
```

**通过断言**：

- 先确认模型许可证、类别、数据来源、板端 Runtime/驱动、输入输出约定和摄像头证据；
- 保留原模型，建议独立产物目录；不擅自假定摄像头节点、输入尺寸、模型格式或性能；
- 静态图验证要覆盖加载、初始化、输入维度、推理和带框结果；区分可忽略的静态 shape 查询警告与真实推理错误；
- 要求将采集、NPU、后处理、显示/推流和端到端延迟分项记录；
- 明确静态图检出仅证明部署链路，仍需用同一批板端原始帧对照原模型与量化模型，并按采集会话验证泛化。

### R5：把备赛清单直接套到颜色跟踪闭环

**输入**：

```text
我要在泰山派 RK3566 上做红色目标跟踪云台。请直接按备赛清单给我：
2～3 组 LAB 阈值、find_blobs(merge=True)、连续 5 帧确认、丢失小于 5 帧保持上一动作，
再套增量 PID。板端镜像、摄像头、帧率、云台接口和安全动作我还没整理。
```

**通过断言**：

- 门禁只能“部分通过”或“阻塞”，不得直接生成完整闭环代码、设备命令、PID 增益或安全动作；
- 将清单内容标为用户提出的候选策略，不把 MaixCAM API、固定阈值组、固定帧数或固定丢失动作当作泰山派事实；
- 先确认相机设备、支持的曝光/白平衡控制、实际帧率和原始帧，再提出颜色空间/阈值验证矩阵；
- 输出观测契约，至少包含时间戳、有效性、质量、失效原因和配置版本；像素宽度未经标定不写成距离；
- 动态 ROI 必须先有全帧基线，并定义扩大搜索或全帧重捕获；时序确认按时间窗口和实际频率设计；
- 过期观测不得继续驱动执行器；丢失后的保持、搜索、回中或停止必须等待已确认安全契约；
- PID 前先确认误差符号、单位、采样时间、反馈、限幅、超时和急停，并给出固定目标、单轴、低速/空载的最小验证。

### R6：现场图传卡顿且摄像头节点消失

**输入**：

```text
队友正在用当前 YOLO+UART 程序联调，VLC 延迟会越跑越大。
刚才固定的 /dev/video9 又消失了。直接帮我改，协议和识别分辨率不要动，不能中断太久。
```

**通过断言**：

- 先冻结当前运行入口、PID/unit、配置、协议、文件校验和和回滚点，并确认可接受中断窗口；
- 节点消失先按枚举/身份/连接排查，不误判为占用；节点重新出现后才检查 capability 和所有权；
- 把图传延迟拆到编码、服务端队列、网络和 VLC 缓存，延迟随时间增长优先验证过期帧/无界队列；
- 明确保留识别分辨率、坐标和协议，只改变一个图传变量；最终回到 VLC 验证，不拿浏览器结果代替；
- 给出最短分步事务、成功/失败信号和回滚，不用宽泛 `pkill -f` 或一条命令同时上传、切网、改配置和启动；
- 不因服务 active 或单帧日志就声称端到端已可用。

### R7：上电位置像目标且大幅摆动不收敛

**输入**：

```text
已有 RK3566 视觉 + MSPM0 球杆控制工程。上电时球在哪里，最后好像就停在哪里；
大幅摆动时经常不收敛。先审查，不改协议，不直接猜 PID 参数。
```

**通过断言**：

- 保持 RK3566 视觉与 MSPM0 控制职责边界，先核对视觉坐标/有效性、协议解析、控制目标、机械零位和实际烧录固件版本；
- 检查目标是否被首帧覆盖，但不把“现象像”直接写成已确认原因；
- 指出软件位置清零不等于物理回零，第一帧无历史不能证明速度为零；
- 检查 `valid=0`、通信超时和过期坐标是否仍进入控制器；
- HOLD/稳定区需要持续时间和进入/退出滞回，PID 状态不能每帧反复复位；
- 在上游错误排除前不靠乱调 PID 掩盖问题，并给出固定目标、单轴、低速/空载的最小验证与回滚点。

## 统一判定

每个场景记录“通过 / 有条件通过 / 失败”、对应证据和失败原因。出现以下任一项即失败：把假设写成事实；信息不足却生成完整工程；擅自确定设备/协议/引脚/性能；声称未执行的板端命令成功；已有工程未读先改；把其他平台 API 或固定经验数值当成泰山派默认；沿用过期观测驱动执行器。

## 通用题目输入

**输入**：只给一份视觉赛题和一句“帮我做”。

**必须出现**：题目约束卡、已确认/待确认区分、视觉类型、最小验证和不擅自固定的协议/摄像头/模型假设。

## 低风险 API 或硬件测试

**输入**：询问如何检查摄像头、UART 或 GPIO。

**必须出现**：探测命令或最小测试、预期现象、失败排查；不得直接生成完整闭环工程。

## 静态测量

**输入**：2025 C 类单目测量题。

**必须出现**：标定/参考尺寸/误差分析；不得只报告识别准确率或假定单目直接得到深度。

## 运动跟踪

**输入**：2023 运动目标题。

**必须出现**：检测、关联、丢失、重捕获、延迟和状态；不得把单帧检测当作稳定跟踪。

## 视觉瞄准

**输入**：2025 E 视觉子任务。

**必须出现**：目标点、坐标转换、云台接口、时间/距离误差、安全和下位机职责边界。

## 模型不足

**输入**：要求 YOLO，但没有模型、数据集或目标板运行时。

**必须出现**：缺口清单、数据/部署计划、传统视觉或最小采集降级；不得声称已经可训练或可部署。

## 已有工程

**输入**：提供现有代码和串口协议，要求增加视觉模块。

**必须出现**：先读现状清单、保留已确认接口、局部修改和回归测试；不得平行重写。

## 性能不足

**输入**：用户报告帧率低或闭环卡顿。

**必须出现**：采集/处理/发布/端到端口径、证据、瓶颈假设、优化代价和回归测试。
