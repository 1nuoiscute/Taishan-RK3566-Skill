# 已有工程与联调接入

用户提供源码、设备树、接线、协议、模型或运行日志时，先读取 `templates/existing-project-change.md`，建立现状清单：入口、启动命令、目录、系统、设备、端口、波特率、协议、坐标、线程/循环、已验证项和当前故障。

若工程已经在板端运行，还要记录源码/固件/模型/配置版本、板端实际文件校验和、systemd unit 或活动 PID、设备/端口所有者和最近可用回滚点。源码正确但烧录或运行的是旧产物时，不能把行为归因给当前源码。

保留用户已确认的接口和安全联锁，只追问会改变本次方案的缺项。先做局部修复和最小验证，不平行重写整个工程。

接入顺序：

1. 原工程能否在当前 VS Code Remote-SSH 环境启动；
2. 输入、视觉、通信和执行是否能各自观测；
3. 本次改动影响哪个接口和验收指标；
4. 只改变一个主要变量完成回归；
5. 再合并到闭环。

用户或队友正在使用现有进程时，默认保留运行状态，先询问或确认允许的中断窗口。不要以宽泛进程匹配、覆盖唯一副本或切换网络作为普通诊断步骤。现场部署、网络切换和图传问题读取 `references/live-debugging-and-deployment.md`。

若原工程中已有协议、引脚、坐标或模型，不因“常见做法”自动替换。若内容不足以证明板端事实，标记为待确认并输出探测步骤。

只有在读取相关源码和配置、记录原工程基线并定位最小修改入口后，才开始改动。若用户只描述“有一个工程”但没有提供可读文件或关键片段，先返回增量改造卡和最小材料清单，不生成平行工程。

交付时分别报告“本地已改”“已上传”“活动进程已切换”“最小功能已验证”和“端到端已验收”；这些证据等级不能互相替代。

## 现有探针的离线基线

涉及本包 scripts/probe_camera.py 的增量需求时，读取配套 tests/test_probe_camera.py，再用 Python 的 -B 选项运行这个纯假对象单元测试；它不打开摄像头、串口或执行器。运行依赖与路径以当前插件资源目录为准。先对照请求是否已经实现，记录测试命令、退出码及断言覆盖，再提出修改。静态阅读发现的问题只是候选：必须指出实际执行分支、复现输入和结果，不能把已经存在的保护逻辑描述为缺失。测试通过只证明其断言覆盖，不能证明未覆盖的帧尺寸变化或板端性能。没有执行条件时明确标为未复验。

纯审查且禁止改文件时，不用“写临时脚本再删除”代替内存验证。运行已有纯假对象测试即可；确需额外假对象，用 Python -B stdin/-c，不能创建文件，也不能把删除后的写入称为未修改。用户明确保留退出码时，包括可选新参数路径也保留既有退出码集合；额外结果用新增 JSON 状态表达，契约变更另行取得授权。
