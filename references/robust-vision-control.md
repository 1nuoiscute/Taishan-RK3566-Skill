# 鲁棒识别与闭环调优

当题目涉及颜色阈值、几何轮廓、动态 ROI、时序确认、相机参数或 PID/云台闭环时使用本参考。这里给出的是候选方法和验证顺序，不是泰山派统一参数。设备控制、阈值、帧数、模型数据量、控制增益和失效动作都必须来自当前题目、当前镜像和目标板证据。

## 1. 先固定观测契约

每个视觉结果至少记录：

```text
capture_ts / processed_ts
frame_id
valid
state
bbox 或轮廓
center_px
size_px
quality
invalid_reason
roi
config_version
```

`center_px` 和 `size_px` 是图像观测量，不自动等于物理位置或距离。只有完成相机标定、参考尺寸或题目允许的尺度模型验证后，才能输出带单位的测量值。传统视觉的 `quality` 是面积、形状、颜色残差或时序一致性等可解释质量量，不要直接冒充模型置信度。

## 2. 相机与光照工作点

1. 先枚举当前设备、格式、分辨率、帧率和支持的控制项，再决定使用 OpenCV、V4L2 或已有采集接口。
2. 保存自动曝光/白平衡收敛后的原始帧和参数；分别测试“保持自动”和“收敛后锁定”的效果。不要假设关闭自动一定更稳，也不要设置设备不支持的控制项。
3. 每个候选工作点记录曝光、增益、白平衡、照明频闪、图像噪声、拖影和饱和区域。只改变一个主要变量。
4. 用题目覆盖的亮度、角度、距离、背景和遮挡组成测试矩阵；单一桌面场景通过不能代表赛场鲁棒。

若 `v4l2-ctl` 可用，先只读记录：

```bash
v4l2-ctl -d <已确认设备> --list-ctrls-menus
v4l2-ctl -d <已确认设备> --all
```

设置命令必须基于枚举结果和用户确认，执行后重新读取实际值并保存前后图像。设备名和控制名不得从其他镜像照抄。

## 3. 颜色与连通区域

- 在采集原始帧上比较 BGR/RGB、HSV/HLS、Lab 或归一化色度；按目标与背景的可分性选择，不把 Lab 当作固定答案。
- 阈值组可以覆盖多个已验证光照工作点，但必须记录每组适用条件、误检和漏检。自动切换阈值前先定义判据，避免在噪声中来回切换。
- 使用形态学、连通域或轮廓合并处理断裂时，记录核尺寸、迭代次数和相邻目标被误合并的风险。`find_blobs`、`merge=True` 等平台专属 API 只能转译为通用意图，不能写进泰山派默认实现。
- 候选筛选至少考虑面积、位置、颜色质量、几何质量和与上一状态的一致性。不要永远选择最大区域；干扰物可能更大。

最小验证输出原图、颜色空间通道或掩膜、所有候选、最终选择和拒绝原因。阈值应外置为配置，并在固定录制序列上回放回归。

## 4. 轮廓、圆与几何

常用候选链路是“灰度/颜色通道 -> 去噪 -> 阈值或边缘 -> 形态学 -> 轮廓 -> 几何筛选”。圆度可按 `4*pi*area/perimeter^2` 计算，但阈值必须用当前分辨率、目标尺寸和断边情况验证；小轮廓的周长噪声会显著放大误差。

- 轮廓法适合边界较完整、面积可约束的目标。
- Hough 圆适合作为边缘型候选或降级路线；必须记录半径范围、步长、误检和计算代价。
- 面积和像素宽度随分辨率、距离和透视变化。优先使用归一化比例或已标定物理范围，不复制固定像素阈值。
- 若像素宽度用于估距，必须验证成像模型、目标真实尺寸、姿态、畸变和工作距离；否则只输出 `size_px`。

## 5. 动态 ROI 与重捕获

动态 ROI 是性能优化，不是正确性的前提。先用全帧基线证明目标能被发现，再启用 ROI。

- 根据上一可信目标、速度估计和处理延迟扩展 ROI；留出与最大位移、尺度变化和检测误差相符的边界。
- ROI 必须裁剪到图像范围，并记录目标靠近边缘、部分出框和镜头畸变时的行为。
- 目标未确认、质量下降、时间戳过期或连续丢失时，按已定义策略扩大 ROI 或回到全帧搜索。
- 即使跟踪稳定，也按时间或风险安排全帧复核；周期由漏检代价和性能预算决定，不使用无依据的固定帧数。

验收同时记录 ROI 命中率、全帧重捕获时间、处理耗时收益和因 ROI 导致的漏检。

## 6. 时序确认、滞回与丢失状态

把“连续若干帧”改写为时间和证据窗口：记录采集/处理频率、窗口时长、最少有效观测、允许间断和进入/退出阈值。帧率变化时，固定 5 帧代表的实际时间会变化。

按题目裁剪状态，例如：

```text
SEARCH -> CANDIDATE -> CONFIRMED/TRACKING -> LOST -> SEARCH
                                         \-> SAFE_STOP
```

- 进入与退出使用不同阈值或质量滞回，避免边界抖动。
- 每次状态转换保存触发观测、时间戳和原因。
- 上一次观测只能在明确的新鲜度时限内用于预测或显示；不得把旧坐标持续标为有效。
- 丢失后的保持、搜索、回中、减速或停止属于安全/控制契约，必须由题目、执行机构和用户确认。默认不得“继续上一帧动作”。

## 7. 模型只作为有证据的路线

是否使用 YOLO/RKNN 由语义、遮挡、背景复杂度和传统路线的失败证据决定。数据量不使用固定张数门槛；按场景覆盖、负样本、类别平衡和独立采集会话设计数据。

- 训练/验证/测试按采集会话或场景隔离，避免相邻视频帧泄漏。
- 覆盖题目允许的光照、距离、角度、背景、模糊、遮挡和无目标场景。
- 记录授权、标注规则、模型/导出/Runtime 版本和量化对照。
- 先验证静态图和同一批板端原始帧，再验证实时采集和端到端延迟。

## 8. PID 与执行闭环

在加入 PID 前先确认：

- 误差定义、原点、正负方向、单位和相机到执行机构的映射；
- 采样时间、观测时间戳、控制发布频率和执行反馈；
- 输出范围、速度/加速度限制、死区、急停和通信超时；
- 目标丢失、观测过期、饱和和重启后的动作。

位置式、增量式、PI、PD 或 PID 是候选实现。离散公式必须与实际采样时间和输出语义一致，不能只抄一个公式。调参先在固定目标、单轴、低速、限幅或空载条件下确认符号，再逐步增加比例、阻尼和必要的积分。加入积分时实现并验证抗饱和；微分项需评估噪声并按需滤波。输出限幅、变化率限制和状态切换复位必须有测试。

不要只用“看起来稳”验收。至少记录上升/稳定时间、超调、稳态误差、抖动、饱和占比、丢失后的停止时间和重新捕获行为。

### 启动、稳定区与固件一致性

- 目标位置必须来自题目、配置或已确认命令；不得在初始化时无意用第一帧观测覆盖目标。
- 软件累计位置清零不等于机构物理回零。没有绝对编码器、限位回零或明确人工水平条件时，电机/摆杆零位只能标为待确认。
- 第一帧没有速度历史，不能自动证明速度为零或已经稳定。接管前使用最少观测、时间窗口和新鲜度门槛。
- HOLD/稳定区使用进入与退出滞回和持续时间。PID 积分、微分或滤波状态只在已设计的状态转换上复位；不得每帧进入中心区就清空动态状态。
- 收到 `valid=0` 或通信超时时立即使观测失效，不能保留 `valid=true` 并继续把历史位置送入控制器。
- 调试结论必须记录当前烧录固件、构建配置和源码版本的一致性；旧 `.out`、旧脚本或旧环境文件仍在运行时，先解决版本来源再调参。

## 9. 分阶段验收

1. 固定图片验证候选提取和拒绝原因。
2. 录制序列回放验证阈值、ROI、时序状态和重捕获。
3. 板端相机开环验证工作点、采集/处理频率和长时间稳定性。
4. 不连接高风险执行器时验证坐标符号、控制器计算、限幅和超时。
5. 固定目标、单轴、低速/空载验证闭环。
6. 按题目场景、扰动和评分指标完成端到端验收。

使用 `templates/perception-control-tuning.md` 保存每轮参数、唯一变量、证据和回滚值。没有目标板与执行机构证据时，只能把相应项目标为“待实测”。
