# 调试顺序

## 0. Remote-SSH 与运行身份

确认 VS Code 当前主机、用户、项目路径、权限、解释器、编译器和启动命令。确保日志来自泰山派，而不是本地终端或另一台服务器。

## 1. 相机和光照

确认设备节点、像素格式、曝光、增益、白平衡、分辨率、实际帧率和连续采集。保存原始帧、支持的控制项和实际控制值；分别验证保持自动与收敛后锁定，不把其他设备参数直接照抄。

打不开时必须按“节点存在 -> 设备身份 -> capture 能力 -> 进程所有权 -> 最小读帧”分层取证。节点不存在不等于被占用；一条 OpenCV 打开失败也不能单独证明占用、驱动缺失或硬件损坏。易变的 `/dev/videoN` 只作为当次事实，优先保存 by-id/by-path 或 udev 身份。现场分诊见 [现场联调、图传与部署](live-debugging-and-deployment.md)。

## 2. ROI、阈值与几何

先检查全帧基线、ROI 和中间图，再检查阈值、形态学、边缘、轮廓、拟合和标定。保存所有候选与拒绝原因，用固定输入或录制序列复现误检，不边看闭环输出边调算法。动态 ROI 还要验证边缘、丢失、扩大搜索和全帧重捕获。

## 3. 模型与数据

确认模型文件、格式、运行时、输入预处理、输出解码、量化和版本。记录加载时间、推理时间、有效输出和失败日志。没有授权模型或数据集时，使用传统视觉验证或明确阻塞。

## 4. 串口与协议

先做单独收发和解析测试，再接视觉；记录原始字节、时间戳、帧边界、校验、超时和下位机反馈。不要在排查阶段同时改变协议和视觉坐标。

区分视觉更新频率和串口发布频率；重复、保持或预测旧观测不会提高视觉帧率。协议切换前冻结版本、测试向量、接收端兼容方式和回滚版本，排查 ROI、图传或网络时不得顺带改协议。

## 5. 闭环、状态机与安全

从固定目标、单轴、低速、限幅和空载开始。先确认误差符号、单位、采样时间和输出语义，再检查有效性、时间戳、丢失、超时、急停和恢复状态。过期观测不得继续驱动；控制调参每轮只改变一个主要变量并保留回滚值。

## 6. 性能与崩溃

区分采集、处理、发布和执行频率；记录 CPU、内存、NPU、串口积压、卡顿、重启和长时间运行。先定位瓶颈，再给带代价和回归测试的优化方案。

图传按“采集 -> 推理/叠加 -> 编码 -> 服务端队列 -> 网络 -> 播放器缓存/解码”分层。延迟随时间增长优先查无界队列和过期帧；延迟稳定但卡顿再查发布频率、编码、无线链路和播放器。识别、预览和录像分辨率分别验收，不用改变识别坐标契约来掩盖图传瓶颈。

## 7. 现场变更纪律

用户要求直接执行时，先完成一个最短可回滚事务，再报告证据；不要用超长一行命令混合上传、杀进程、改网络、改配置和启动。队友正在联调时先确认中断窗口，使用精确 unit/PID 管理进程，不用宽泛 `pkill -f`。部署前后核对本地/板端校验和、实际配置、活动入口和回滚版本；`service active` 不等于相机、识别、串口和图传均已可用。
