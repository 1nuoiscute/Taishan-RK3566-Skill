# DSH 1.6.0 合成会话证据

这些 JSON 保存真实会话输入、完成状态、实际工具调用摘要、完整最终回答和私有原始日志 SHA256。已删除本机路径、会话上下文与推理消息；认证文件不属于公开证据。平台为 DSH 0.2.0-rc.2，请求模型为 deepseek-flash，均没有板端连接。

R1/R7 使用干净工作目录重跑，其他为同批完整会话。该批在模型/采集参考纠正后、最终加入配套离线测试指引前执行。completed 只表示模型返回完整，不代表行为断言全通过。R3 为真实失败样本：把已经跳过的首个 FPS 样本说成入窗，并错误声称 framesize 第一帧就稳定。实际脚本要求至少一个完整窗口；既有假对象测试同时断言 history_size >= 5 和 total_frames >= 6。发布候选已补交付这些测试并要求先运行基线，最后复测状态见上级发布记录。

早期 maxTokens=2400 导致多个场景 max-tokens/空回答，不能作为通过证据。随后提高预算。相同版本/文件名的包被安装器缓存时曾返回旧资源；已通过 hash 命名归档及源码/安装资源逐字节比对检测并规避。初始 R4 曾把案例 NHWC/特定 YOLOv8 导出当通用要求，R6 曾默认开相机且说无需停程序；其源文件冲突已修正，保留失败事实。

条件通过表示提供了合理离线框架，但缺少部分工程验收条目，不能当作实现完成或硬件验收。

最终源码安装复测曾因本地 CRLF 与 Git 中 LF 的字节差异触发严格比对；按既有 .gitattributes 的 LF 规范统一发行资源后，同一 GitHub 候选包核对通过。这不是运行逻辑缺陷，也没有放宽字节断言。

R3-offline-baseline.json 记录额外执行的纯假对象证据：FPS 首样本没有填入窗口，两个分支均必须积累完整窗口。保留 open-time 尺寸局限。这份证据修正错误读码，不替代待授权的真实模型复测。

授权后复测新增两项明确失败记录：R3-temporary-write-failure.json 保留写临时脚本后删除却声称未改文件的行为；R2-zero-duration-failure.json 保留契约未知时建议零秒打开串口及未经验证的静态疑点。删除文件或不发送数据均不消除其越界事实。最终 R3-final.json 则只读并实际运行打包测试，旧代码误诊及临时文件写入已消除，退出码集合保持原样。最终核心门禁的生成入口 SHA256 及真实测试输出另存，不覆盖失败样本。

R2-final.json 来自零秒打开参考修订后的最终复测，只读执行既有假对象测试与 stdin 内存 UART 假对象，明确身份/配置/所有权/副作用条件缺失时不打开端口。R1-final.json/R3-final.json 来自同一生成入口的核心门禁复测；R2 后续参考修改仅补明零秒串口打开边界。读数、成功返回和配套 camera 测试均不能证明真实 UART 硬件。
